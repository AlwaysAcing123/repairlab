# RL plan — November 4, 2026

Written **before** any RL result, so its rules cannot be fitted to the outcome. Nothing
here is a model score.

## Why RL, and what it can and cannot show

The recovery adapter now revises after a failed test, but it mostly repeats or
reshuffles its first idea instead of using the test output. Supervised training can
only copy written demonstrations; RL rewards whatever actually passes. That is a
reason to try it, not evidence that it will help on unseen programs.

Success still requires both public and private checks.

## Method, fixed now

Each **cycle** samples 4 attempts per RL program from the current adapter, 120 in
total, under the evaluation tools and limits. They are graded locally in Docker, as
always. The update then runs on Kaggle and becomes the next cycle's adapter.

| Setting | Value |
| --- | --- |
| Start | Recovery adapter `84c8b61f…`, the best supervised checkpoint |
| Cycles | 6, so 720 sampled attempts |
| Sampling | temperature 1.0, no top-k or top-p truncation |
| Reward | 1 for an explicit submit passing every public and private check, else 0 |
| Advantage | reward minus the mean of the same program's 4 attempts this cycle |
| Trained attempts | only those with a nonzero advantage; every generated token shares it |
| Objective | clipped importance ratio (0.2) against the sampling policy, token mean |
| Optimizer | AdamW, learning rate 0.00002, 4 steps per cycle, reset each cycle |
| Regularization | gradient clip 1.0; no KL penalty |
| Checkpoint | **the adapter after cycle 6**; earlier cycles are evidence only |

Sampling at temperature 1.0 without truncation means the update scores exactly the
distribution it sampled from. Programs whose 4 attempts all pass or all fail give no
signal and are skipped. The update re-renders each prompt and requires it to hash to
the exact token ids sampled. Each completion is scored on its saved token ids, never
re-tokenized text.

The budget is small: 24 optimizer steps in total. A null result is a real
possibility, and it would be reported as one.

## Evaluation and decision rules

1. **Autonomous development comparison.** Original, first adapter, recovery adapter,
   and RL adapter in one run on all 24 development tasks under the frozen rules. The
   first three reruns are also a determinism check against saved trajectories.
2. **Seeded recovery probe.** Recovery versus RL adapter, as before. Not an autonomous
   score.
3. **Final test, opened once.** All four arms on the 24 sealed tasks, autonomously,
   after steps 1 and 2 and whatever their outcome. No checkpoint is selected on it,
   and all four results are reported.

**RL helped** only if the RL adapter solves more development tasks autonomously than
the recovery adapter in the same run **and** passes at least as many seeded tasks.
Differences of a few tasks are reported with the exact sign test and are not called
reliable. Rising training reward alone is not evidence of better repair.

If RL fails technically, it is diagnosed and rerun in a new directory, and the final
test stays sealed until an RL checkpoint is frozen. `scripts/run_final_test.py`
records its opening in `artifacts/final-test-registry.json` before uploading anything
and refuses a second opening.

## Launch

```sh
TOKEN=~/.kaggle/access_token
KAGGLE=.venv/bin/kaggle

python3 -B scripts/run_rl_training.py --output artifacts/native-rl-training-v1 \
  --token-file "$TOKEN" --kaggle "$KAGGLE"
.venv/bin/python -B scripts/verify_rl_training.py artifacts/native-rl-training-v1 --regrade \
  --tokenizer artifacts/native-recovery-training-v2/extracted/adapter/tokenizer.json

python3 -B scripts/run_matched_comparison.py --arms original,supervised,recovery,rl \
  --recovery-run artifacts/native-recovery-training-v2 --rl-run artifacts/native-rl-training-v1 \
  --output artifacts/native-rl-comparison-v1 --token-file "$TOKEN" --kaggle "$KAGGLE"
python3 -B scripts/verify_matched_comparison.py artifacts/native-rl-comparison-v1 --regrade

python3 -B scripts/run_matched_comparison.py --arms recovery,rl --seeded \
  --recovery-run artifacts/native-recovery-training-v2 --rl-run artifacts/native-rl-training-v1 \
  --output artifacts/native-rl-seeded-v1 --token-file "$TOKEN" --kaggle "$KAGGLE"
python3 -B scripts/verify_matched_comparison.py artifacts/native-rl-seeded-v1 --regrade

python3 -B scripts/run_final_test.py --open-sealed-final-test \
  --recovery-run artifacts/native-recovery-training-v2 --rl-run artifacts/native-rl-training-v1 \
  --output artifacts/native-final-test-v1 --token-file "$TOKEN" --kaggle "$KAGGLE"
python3 -B scripts/verify_matched_comparison.py artifacts/native-final-test-v1 --regrade
```

`--resume` continues an interrupted RL run from its last completed cycle. Expected
quota use is about 4 to 6 GPU hours, an estimate until the first cycle runs.

## Incident during the run

Round 7 of the first cycle ran out of GPU memory while sampling. Peak memory had
climbed from 4.3 to 11.7 GiB as the longest prompt grew to about 2,500 tokens, because
padded attention grows with the square of prompt length and batches of 16 were capped
only linearly. Sampling batches are now capped by `(batch size) × (longest + 512)²`,
which leaves short prompts in batches of 16. No setting in the method changed.

That partial cycle never reached an update. It is kept as `cycles/1-abandoned-1`, the
run resumed from the recovery adapter, and `source-snapshot-resume-1/` holds the fixed
code. Each round's uploaded notebook also embeds the exact runtime it used.

Cycles 1 and 2 then completed (mean training reward 0.325 and 0.367). In round 6 of
cycle 3 the Kaggle CLI exited with an error after it had downloaded everything:
fetching the same output again gave a byte-identical archive. Downloads are now
retried up to three times, and each failed attempt's log is kept. Cycle 3 restarted
from the cycle 2 adapter. The partial cycle is kept as `cycles/3-abandoned-1`, and
`source-snapshot-resume-2/` holds the code.
