# Third sealed final test — November 9, 2026

This is the sealed test for the RL-first phase ([plan](rl-first-plan-20261107.md), Splits
and Addendum 1, item 4). It holds 96 new programs, each with a hand-written bug. The
generated bug for each program is chosen later, by a fixed seed and before any model
runs; that is not part of this set. Nothing here is a model score.

**No model has seen these tasks.** A separate agent wrote them. It was given the set's
specification and the earlier programs to separate from, and it saw no model output,
GPU run, or result of this phase. It ran no model and no Kaggle command.

## Contents

`repairlab/final3/programs.py` holds 96 single-function repair tasks, in their own
package so earlier fingerprints stay meaningful.

Every task has 3 to 5 public examples and a small, finite input domain. Domains range
from 25 to 1,368 inputs, with a median of 256. Each task also has a correct alternative
written a different way.

mutation rule makes, such as misreading the specification, a plausible but wrong

The largest kind is 14 of 96 (14.6%), under the 20% cap. Every bug keeps the signature,
finishes on every input, and fails at least one public example, so every task shows a
real failing test. On `balanced-journal`, `even-shares`, `order-transition`, and
`elapsed-label`, only a public example exposes the bug, because the bug is a single
edge case. Success still requires every public and private check to pass.

## Controls

In the pinned Docker grader, **all 384 authored controls matched**. On every task, the
bug fails, the reference and the alternative pass, and a copy that hard-codes the public
answers passes the public examples and fails overall.

## Separation

`final3_leakage_report()` compared each new task with all 156 earlier programs, plus the
12 legacy warm-up programs: 168 entries in all, covering pilot, curriculum training,
first final test, RL, and second final test. That is 16,128 pairs, with **no hard
failures**. `final3_humanevalfix_report()` compared the new tasks with all 135 converted
HumanEvalFix tasks, dropped ones included: 12,960 pairs, again with no hard failures.

The first draft had 37 near pairs. Every pair was read. Where the closeness was real,
the draft was changed:

- **Short bugs.** Six bugs were one-liners that matched an earlier one-liner after
  names were anonymized: `time-before`, `title-words`, `code-window`, `expand-tabs`,
  `merge-ready`, and `add-padded`. They were rewritten as fuller, still realistic
  mistakes of the same kind.
- **A replaced program.** `highest-altitude`, a running maximum of prefix sums, was too
  close to development task `running-totals`. It became `cycle-length`.
- **Weak domains.** The inputs for `subsequence-of` could barely tell a subsequence from
  a substring, which made it match development task `allowed-status`. The inputs for
  `even-shares` were almost always False. Both domains were widened.

The remaining 12 near pairs are pinned in `REVIEWED_FINAL3_NEAR_PAIRS`, each with its
reason. All 12 are behavior matches on inputs where one side barely runs. In six, the
second argument is empty, so the other program returns its first argument unchanged. In
one, the guessing loop never starts. In five, a list check walks the other program's
strings, and both return False on almost all of them. None shares an algorithm or a fix.
A new near pair fails the tests until someone reviews it.

## Sealing

- `reject_final3()` refuses these tasks by content in any model-facing path, even under
  another ID. It matches the specification, buggy, reference, or alternative source.
  Every earlier program set and every HumanEvalFix task passes it.
- No script loads the tasks, and no notebook contains them; a test pins both.
- The manifest records zero model evaluations.
